# Ask Intros introduction playbook release

This release adds one substantial, indexable resource at `/warm-introduction-playbook`, not a bulk series of near duplicate keyword pages.

## What people can learn

- How to define a useful business outcome before requesting a particular executive.
- The Ask Intros Why me, Why them, Why now context framework.
- Why each side's permission matters and how to avoid leaking private relationship context.
- Two distinct sample messages: a request to the connector and the recipient's first agreed conversation request.
- A short decision checklist and a practical follow up that respects the people who made the connection.
- A clear statement that Ask Intros does not guarantee introductions, funding or sales.

## Search readiness

- Uses the existing server-rendered public product layout, Organization/Website/WebPage identity graph, canonical URL and title/description fields.
- The public homepage and the guide navigation expose the resource via accessible internal links.
- The route opts into the automatically generated sitemap.
- Both local HTTP tests and daily production monitor now include the resource.
- No new account permissions, private members, analytics integrations, migrations or generated claims.

## Measurement and verification

- Run the dedicated Public Search Visibility workflow after code review and ensure the new page appears in raw HTML and sitemap.
- The GitHub-only change must reach Lovable's synced commit and production publishing separately.
- Use the admin Search Visibility dashboard's verified Google Search Console Pages.csv export to decide whether a page attracts impressions, rather than assuming it will rank or be cited.
- Do not create bulk thin pages or claims of measured response rates. Google's documented guidance prioritizes people-first content, indexable HTML and internal linking for both standard and AI Search experiences.
