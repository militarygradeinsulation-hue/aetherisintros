# Social and Business views

Social View uses the owner-supplied `aetheris-bridge.zip` from October 24, 2026, matching the published Commons application. The original source lives in `src/bridge-reference`; `manifest.json` pins SHA-256 hashes for every copied file, including required reference helpers placed in previously absent host paths. Do not edit these originals to implement integration.

Home, People, profiles, navigation, demo messages, introduction cards, radar, portraits and logo use the original components. Live messaging preserves the original Bridge message body, composer and relationship context, with host integrations for the requested mobile inbox, member recipient picker and readable header controls. The existing Ask Intros controller supplies send/retry behavior and canonical thread IDs. One live messaging controller serves both views. The source check verifies the untouched Social message body, composer and relationship context. The mobile-messages browser check covers the host controls, recipient-specific drafts and confirmed sends in both views.

The original Commons stylesheet, font declarations and root stylesheet are preserved. `scripts/bridge-reference/styles.mjs` extracts the original Commons theme definitions and generates Social-only selector scopes and a CSS layer namespace. It does not rewrite design declarations. Business retains its dashboard, sidebar, tables and styling. The view switch sits outside the original navigation. Vite redirects reference-local imports to the original logo and avatar implementations without editing their checked-in source.

Both presentations use canonical member records and existing post, introduction and connection callbacks. `PersistentBridgeFeed` moves one portal container between presentation slots, retaining the live feed controller and draft even while Bridge's Posts tab is hidden. Original demo composer state, replies and directory filters remain internal to their original components: each view retains its own draft and filters across view switches, but demo draft and search text do not mirror between views. Submitted records still use the shared callbacks. Reference rendering is retained, including its original treatment of post media.

The original logo asset is served at its original asset URL and uses CSS-only crops. No Bridge environment configuration, credentials, migrations or account records are imported. Authentication, other workspaces, modal controllers and host integration remain Ask Intros code. This is not a byte-identical replacement of the entire application; source equality applies to the manifest files and the explicitly checked live-message regions.

## Validation

Run `node scripts/bridge-reference/check.mjs` and `node scripts/bridge-reference/styles.mjs --check` to verify original source and generated style scope. Run TypeScript, the production build and the relevant browser regressions. `scripts/experience-check/run.mjs` verifies the Commons composition, original glass tokens, canonical feed DOM retention, per-view drafts and filters, message draft retention, appearance preference and mobile width. Demo checks do not establish authenticated production persistence.
